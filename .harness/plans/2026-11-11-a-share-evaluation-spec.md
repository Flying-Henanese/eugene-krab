# A 股市场研究 Agent 评测工具 v1

## Problem Statement

维护者需要在同步上游、调整研究工作流或更换国内模型之后，确认 A 股研究质量是否退步。普通单元测试能验证数据处理逻辑，却不能直接回答：Agent 是否选对工具、是否使用正确报告期与财务口径、是否准确换算单位、是否如实处理缺失数据，以及是否遵守现有中性技术分析和子代理边界。

当前评测入口独立于正常 CLI、Gateway 和定时任务，但主要围绕原有金融题库，受测模型和裁判仍依赖海外模型。上游已增加 rubric 评分、模型参数、固定种子抽样和结果展示；本地 stash 又有 A 股题库、行为检查和人工复核草稿。需要整合这些已有能力，形成面向 A 股、使用国内模型、可以重复执行和审查的独立评测工具。

## Solution

提供手动触发的命令行评测工具，首版默认评测 A 股研究 Agent。维护者选择题目、受测模型、裁判方式和运行规模，运行真实 Agent 后获得每题答案、可观察调用轨迹、逐项语义评分、确定性行为检查、耗时和失败原因，以及本地汇总报告。

保留上游终端进度界面的形式，同时支持无交互输出和不调用外部服务的预演。自动评分仅使用已接入的国内模型；也可只导出人工复核包。正常聊天、飞书/WhatsApp 和定时任务不会执行评测或等待评测结果。

## User Stories

1. As an A 股研究工具维护者, I want 手动启动独立评测, so that 我能验证改动而不影响日常研究流程。
2. As an 维护者, I want 默认使用 A 股题库, so that 我不必修改海外股票评测代码才能开始验证。
3. As an 维护者, I want 指定受测国内模型和供应商, so that DeepSeek、Kimi、GLM 及显式供应商配置都能被正确调用。
4. As an 维护者, I want 单独指定国内裁判模型, so that 我能将被测能力与评分职责分开。
5. As an 维护者, I want 默认阻止同一供应商和模型自评且允许显式覆盖, so that 自评风险是可见选择。
6. As an 维护者, I want 通过人工模式跳过裁判调用, so that 我可以人工审查答案且无需裁判密钥。
7. As an 维护者, I want 按稳定用例 ID 运行单题或多题, so that 我能复查具体回归。
8. As an 维护者, I want 运行全量、分类快速集或固定种子抽样, so that 我能控制评测规模并重复选择同一组题。
9. As an 维护者, I want 预演显示选题、依赖和配置问题, so that 我能在产生 API 调用前确认运行范围。
10. As an 维护者, I want 只检查所选题需要的数据源, so that 没有新闻搜索密钥时仍可运行纯结构化财务题。
11. As an 维护者, I want 用固定报告期和可核验来源的题目检查财务数值, so that 答案不会因为市场每天变化而无故失分。
12. As an 维护者, I want 检查归母净利润、集团净利润及现金流字段的区分, so that 看似接近但口径错误的回答能被识别。
13. As an 维护者, I want 检查元、万元、亿元和百分比计算, so that 换算和量纲错误不会被语言流畅性掩盖。
14. As an 维护者, I want 检查日周线、复权方式和未完成周线说明, so that 技术面回答保留必要证据条件。
15. As an 维护者, I want 检查单股、新闻、技术和全市场情绪问题的路由边界, so that Agent 不会扩大任务或混用工具。
16. As an 维护者, I want 检查结构化基本面、新闻和技术面综合时的来源与限制, so that 综合答案有可追溯依据。
17. As an 维护者, I want 允许符合现有规范的多种调用路径, so that 评测不会把一种内部实现误当成唯一正确答案。
18. As an 维护者, I want 检查研究子代理的边界和可观察调用预算, so that 委派不会失控或替代主代理综合。
19. As an 维护者, I want 单独显示语义得分与行为检查结果, so that 我能区分答错、选错工具和运行失败。
20. As an 维护者, I want 对每条 rubric 获得判断与理由, so that 我能审查裁判是否合理。
21. As an 维护者, I want 将 Agent 错误、超时、裁判错误和报告上传错误分别记录, so that 基础设施故障不会伪装成答案错误或通过。
22. As an 维护者, I want 控制并发、超时和取消并保留已完成结果, so that 评测不会无限等待或丢失整批工作。
23. As an 维护者, I want 本地保存机器可读结果和简明报告, so that 我无需远程平台也能审查和比较运行。
24. As an 维护者, I want 记录题库版本、选题、模型配置和代码状态, so that 我能判断两次结果是否具有可比性。
25. As an 维护者, I want 在终端查看进度或以无交互方式运行, so that 本机终端和脚本都可使用同一评测流程。
26. As an 维护者, I want 报告明确区分待人工评分、不可观测和失败, so that 缺少评审或轨迹不会被算成成功。
27. As an 维护者, I want 默认不上传题目、答案和轨迹, so that 评测数据保存在本地并由我决定是否启用远程追踪。
28. As an 开发者, I want 自动测试使用模拟 Agent 和裁判验证完整流程, so that 测试无需真实密钥、网络或付费调用。

## Implementation Decisions

- **运行边界**：独立入口，复用现有 Agent 执行、工具注册、配置解析和上游评测界面；不接入聊天、Gateway、心跳或定时任务的正常请求链。首版默认 A 股题库，保留既有非 A 股入口兼容性，但不扩展其能力。
- **整合策略**：以本地 A 股草稿为起点，逐项对照上游模型参数、rubric、抽样和界面实现；保留行为检查、人工复核和 A 股题库。它们目前只是 stash 中的未验收草稿，不能直接认定为完成。修正与现有工具契约不一致的断言，不为旧草稿保留错误约束。
- **模型配置**：受测 Agent 和裁判各自有独立的模型、供应商参数；显式参数优先于相应已有配置。复用 DeepSeek、Moonshot、GLM 适配、推理参数与显式供应商逻辑。无法解析出国内模型时在预检中要求指定，评测不得悄悄回退到 GPT 或 Anthropic，也不改变正常应用的全局默认模型。
- **裁判模式**：自动模式使用国内模型输出结构化逐项判断；人工模式只执行 Agent、行为检查和导出复核包，不构造裁判客户端、不要求裁判密钥。相同供应商和模型身份默认禁止自评，显式允许时写入报告。
- **命令行能力**：支持题库选择、重复指定用例 ID、全量、分类快速集、固定种子抽样、受测及裁判配置、人工/自动模式、并发、单题超时、无交互输出及预演。无效 ID、空选题、重复 ID、非法数量与互斥参数在运行前报错；重复选择同一 ID 可以去重并明确说明。
- **预演与预检**：预演只读题库和解析配置，输出选题与依赖检查结果，不创建 Agent、模型客户端或远程追踪客户端，不调用网络、不写生产运行状态，也不打印密钥。实际运行只要求选中用例声明的数据源；未满足的必要条件阻止该次启动并说明缺项，辅助字段不可用由相应用例的部分数据契约处理。
- **题库格式**：沿用上游可编辑 CSV 形式和已有解析基础。每题至少包含稳定 ID、中文问题、题型、参考答案、rubric 与必要的数据源依赖；可选行为预期和参考来源。稳定 ID 不依赖行号。启动前验证必填项、重复 ID、rubric、来源和行为配置，不能静默丢题。
- **首版题库范围**：至少 12 个经审查的中文用例，覆盖单股综合、窄技术问题、固定报告期财务数据、归母口径与单位换算、经营现金流与自由现金流区分、多股同口径比较、研究子代理边界、全市场情绪、数据不可用/部分结果、复权与未完成周线、窄新闻问题，以及条件依赖预检。复用六个已有草稿用例，补足缺少类别；草稿中的数值和来源必须重新核验后才能作为金标准。
- **事实与动态行为分开评测**：固定事实题使用明确报告期、字段、单位、币种、版本及可核验来源，保存来源取得时间；不能只用“最新”作为固定数值金标准。动态新闻、市场情绪和综合题主要评估题目声明的证据条件、引用、路由与限制，不把过时的实时数值当固定答案。没有可靠金标准的事实项不能伪装成已验证评分项。
- **评分规则**：沿用 correctness 与 contradiction 原子 rubric。语义得分为通过的正确性项占比；触发经裁判确认的实质矛盾时语义得分为零，并保留理由。零正确性项、缺失/重复/未知裁判项或非法结构视为数据或裁判错误，不能静默补成通过。
- **行为规则**：仅依据外部可观察证据检查工具、技能、子代理类型、可观察预算及题目明确禁止的输出。支持等价合法路线；宽泛综合题可允许主代理直接搜索或隔离研究子代理，窄技术题保持直接工具边界。不得评估隐藏思维链。轨迹缺失或子代理计数无法观测时标记不可观测，不能按零次调用判定通过。
- **统计语义**：语义得分、矛盾、行为门禁和运行状态分别保存。自动模式的严格通过须同时满足有效满分语义结果、全部必需行为检查通过、无运行/裁判错误；人工模式语义分数为空且状态为待审，不计入自动通过。报告列出总选题数、完成数、待审数、错误数、行为通过率、有效语义均分、严格通过数与相应分母，不能隐藏失败题来提高通过率。
- **并发与生命周期**：复用评测运行器组织限流、Agent、裁判、事件和结果输出；单题超时覆盖该题的 Agent 与裁判阶段，失败不阻止其他题完成。取消后停止排队与新调用，向在途调用传递取消信号并保存已完成结果。报告标记未完成题。遵守现有 Agent/研究子代理硬预算，不另外扩大权限或预算。
- **运行隔离**：评测使用无交互通道，不带入聊天历史和私有记忆，不绑定 Bash、交互提问、生产任务管理、外发消息或文件修改工具。使用现有工具过滤和运行上下文能力实现，不另建一套 Agent。评测产物写入专用本地目录；不重写生产会话或模型设置。
- **本地报告**：自动、人工两种模式都保存版本化 JSON 与简明 Markdown 汇总，逐题增量保存。至少记录运行 ID、创建时间、题库内容哈希、固定种子、所选 ID、模型/供应商及相关推理配置、裁判方式、rubric/提示词版本、提交号及未提交代码状态摘要、逐题答案与可审查工具结果摘要、检查、耗时、可获得的 token 用量和分类错误。不保存密钥或未经筛选的私有运行目录。
- **人工复核**：导出问题、参考来源、答案、轨迹摘要、行为检查和逐项待审 rubric；执行失败的题标为不可评分。首版交付可人工阅读的复核包，不新增人工打分平台或导回工作流。
- **展示与可复现性**：终端界面和无交互模式消费同一运行事件与结果。固定种子只保证选题与顺序可复现，不承诺真实模型输出或在线市场数据完全一致；报告明确区分这些因素。
- **远程追踪**：保留上游 LangSmith 集成作为显式可选能力。默认只写本地；即使环境中存在追踪配置，也不能意外上传题目、答案和轨迹。追踪失败单列为附加错误，不改写已完成的研究评分，不丢失本地结果，不要求登录或上传才能完成评测。
- **集成顺序**：先固定当前第二、三批已验证改动的基线，再合并评测相关内容；单独处理 stash 中与评测无关的分析、技能和输出文件，禁止整包恢复覆盖当前改动。原 stash 保留到逐项核对完成，提交与恢复操作沿用明确授权规则。

## Testing Decisions

- **用户已确认的主要测试边界**：输入用例与配置 → 完整评测流程 → 评分、行为检查及本地报告。主要验收在这个最高层边界完成；通过现有 Agent 执行和裁判调用接口注入模拟依赖，避免为每个内部函数建立新的测试接口。
- 好的测试观察公开输入/输出、可见事件、报告内容、失败状态及外部调用次数；不锁定私有方法、内部目录结构、隐藏推理或无业务意义的中间步骤。
- 完整流程回归覆盖：正确答案、事实错误、实质矛盾、允许的替代路径、错误工具/口径、数据部分可用、不可观测轨迹、Agent 错误、裁判结构异常、超时、取消、并发上限、待人工复核以及追踪失败；失败项必须保留在输出和正确统计分母中。
- 固定相同题库内容、参数和种子，验证选题 ID 与展示顺序一致；不同并发完成顺序不改变题目身份和最终稳定排序。题库或评分契约变化必须反映到相应哈希/版本记录。
- 测试国内受测模型与裁判配置的优先级、显式供应商、自评阻止及人工模式不调用裁判。没有国内配置时明确失败，不发起海外请求。
- 无密钥、无网络的预演测试验证数据集可读、元数据校验、依赖诊断和零外部副作用。模块导入和普通单元测试不得触发真实评测。
- 在临时运行目录执行报告及设置相关测试，验证本地增量结果完整、取消后的部分结果可读，且不读取或清理用户生产缓存与私有状态。
- 现有先例包括上游题库、抽样、rubric 与参数测试，本地 stash 的行为门禁和人工复核测试，以及当前国内模型请求体、工具预算、非 CLI 工具过滤和 Gateway 配置优先级测试。复用这些已有边界，新增测试重点放在缺少的整合流程。
- 实现完成后运行相关 Bun 测试、类型检查、文件隔离的全量测试和差异检查。真实国内模型冒烟评测独立手动触发，记录实际执行规模与结果；没有执行时明确标记未验证，不以模拟测试冒充真实准确率。

## Out of Scope

- GPT、Anthropic、Google、xAI 等海外模型适配及为它们升级依赖；删除现有供应商代码或改变日常应用的全局默认模型。
- 交易收益、择时、买卖胜率、策略回测、未来价格预测、自动交易；本工具评估研究质量，不构成投资策略有效性证明。
- 在日常聊天、飞书/WhatsApp、心跳、定时任务中自动评分、拦截答案或增加在线裁判步骤。
- 改造生产研究工具、主 Agent 架构、子代理预算或公开技术分析契约来满足某个测试；发现生产缺陷另行记录，不能通过放宽评分伪装修复。
- 全市场大规模基准题库、自动生成金标准、每日行情自动更新、自动刷新参考答案或长期排行榜。
- 新建 Web 平台、数据库服务、裁判标注系统、人工评分导回闭环、自动报告对比界面或多模型矩阵调度；首版可对照本地报告人工比较。
- 强制云端追踪、自动上传、CI 中的付费真实评测、自动部署、恢复整个 stash 或未经授权提交/推送。
